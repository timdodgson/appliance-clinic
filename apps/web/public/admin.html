    Live diagnostic system · production

    What a live test touches

    • Each message goes to the production diagnostic system — the orchestrator, Part Finder, Error Code MCP and RAG — exactly as a customer message would, using the AI routing currently set in Settings.
    • Turns belong to one conversation: like a customer’s browser, the Live Test sends back the signed conversation-state token the API returned, so retained facts, identity and journey progress carry from turn to turn. The token stays in this browser tab only and is never shown. New conversation discards it.
    • No conversation transcript is saved and nothing in Knowledge, Error Codes, Media or Safety changes. The diagnostic engine keeps its usual time-limited conversation state, as it does for every caller.

    Run curated scenarios as a batch through the shared test runner, then review the results. This is not GOLD and does not admit scenarios to GOLD.

    Batch runs affect production while they run

    • The test runner sends every scenario to the production ApplianceClinic API.
    • For the whole run it switches the live AI routing (Settings → AI configuration) to the run's setup. Real customer conversations during the run use that same routing — including OpenAI for a frontier experiment.
    • Only the fields the run needs are changed (COMPOSE routing / model). The exact pre-run configuration is saved first and restored — and verified — when the run completes, fails, times out or is cancelled. If the configuration was changed by someone else meanwhile, it is not overwritten: the run reports a restore conflict for an admin to resolve.
    • One run at a time may own live routing. Settings blocks diagnostic-inference changes while a run owns it. Both the temporary change and the restore appear in Settings change history.
    • Runs never save customer conversation transcripts. Results and engineer reviews are stored with the test history only.
