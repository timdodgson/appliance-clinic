# LLM-led rebuild: independent evaluation

The journey architecture lost an independent blind benchmark 94–6 to a general-purpose assistant
([report](independent-100-case-benchmark.md)). [ADR 0020](../adr/0020-llm-led-diagnosis-with-deterministic-guardrails.md)
replaced it with LLM-led diagnosis inside a deterministic guardrail kernel ("ac2"). This page is the evaluation of that
replacement: the same frozen 100 cases, plus a held-out set frozen before any tuning, judged blind against the old
architecture and the same general assistant.

## Method

| | |
|---|---|
| **Systems** | **New AC (ac2)**: the frozen candidate, release 20.13 (commit `54a18d4`; release 20.14, `d3a529c`, only redacted host names from provider error logs and was live during the run), on live production through the service-authenticated benchmark path (`AC2_MODE=benchmark`), reasoning with the production model (Qwen 3.6 35B-A3B on LM Studio). **Old AC**: the journey architecture on live production. **General assistant**: `claude-opus-5-5`, generic system prompt, no tools, isolated |
| **Cases** | `evaluation/independent-100/cases.json` (sha256 `f212047f…`, unchanged since its freeze) and `evaluation/heldout-25/cases.json` (31 cases, sha256 `8db4dbb7…`, committed in `6f55ee1` before any ac2 tuning). Neither file was edited |
| **Customer** | The same simulator (`claude-sonnet-5-5`) answering only from each case's fact bank, up to 8 customer messages |
| **Judges** | Primary `claude-fable-5-1`, second `claude-sonnet-5-5`; neither is used by Appliance Clinic. Prompts, rubric and critical-failure definitions are the independent-100 ones, unchanged. Transcripts are masked; pairwise order is seeded |
| **Second judge** | Every transcript with a critical flag, every score/pairwise disagreement, and a 10% sample |
| **Baselines reused** | On the independent 100, old AC and the general assistant are the original frozen runs and judgements. On the held-out set, all three systems were run and judged in this programme |
| **Development** | The independent 100 was used as development evidence (two 24-case subsets, releases 20.4–20.13), by failure class only. The held-out set was not run on ac2 until the candidate was frozen |
| **Harness** | `evaluation/rebuild/` (runner, judge, analysis): the independent-100 harness with a third system and a second case set; nothing in `evaluation/independent-100/` was changed |

## Verdict

**Improved but not ready.** The new architecture is a large improvement on the journey architecture (83–17 head to head,
usefulness 2.73 against 1.46, invented evidence 4% against 19%, looping 11% against 38%), and the held-out set confirms
it (27–4, 2.81 against 1.06). It does not meet the targets against the general assistant, on either set, and misses
the safety target on the independent 100. **Customers were not cut over.** The new engine stays dormant in production
(`AC2_MODE=benchmark`, reachable only by the signed benchmark path), the journey architecture keeps serving customers,
and the branch that deletes the journey controller (`r2/retire-journeys`) is not merged.

## Why it lost

Read from the critical-failure evidence and the pairwise reasons; the counts are conversations on the independent 100.

| Failure class | Count | Typical evidence | Where it sits |
|---|---|---|---|
| Confident conclusion without evidence | 17 (11 confirmed) | "almost certainly an earth-leakage fault … replace the damaged module" without knowing which device trips | Reasoner calibration. The verifier checks claims about the *customer*, not diagnostic confidence |
| Repeated or blocking questions | 11% looping, 5 blocking | Asked the customer to plug something into a socket after they said the appliance is hard-wired | Reasoner state tracking; the repeat guard catches verbatim repeats only |
| Unjustified part | 5 (4 confirmed) | Part proposed after one symptom | Part gate allows a part when the model calls the assessment narrowed; it does not judge whether narrowing was earned |
| Invented customer evidence | 4 (2 confirmed) | "Because there was a burning smell" when the customer said "no burning that I could see" | Verifier misses: paraphrase with flipped polarity inside a causal clause; an unstated accessory ("the Laser Slim Fluffy head") |
| Unsafe DIY | 2 (both confirmed) | "run it empty for just 5 minutes and stay nearby" after a burning smell; "turn the isolator off … then remove the faceplate" | Prohibited-advice patterns did not cover these phrasings |
| Missing safety stop | 2 (both confirmed) | An out-of-scope kettle that trips the kitchen supply got only the scope reply; an old tumble-dryer model in a recall programme was not flagged | Scope reply returned before the supply-trip copy; recall store had no strong match for the model |

The pattern behind the score gap is the reasoner itself. On the dimensions the kernel controls, the new engine is close to
the general assistant (no-fabrication 3.73 against 3.93, part quality 3.59 against 3.63). On the dimensions the model
owns, it is well behind: diagnostic usefulness 2.76 against 3.60, question quality 2.42 against 3.09, calibration 2.77
against 3.30. The production model (Qwen 3.6 35B-A3B, fixed by the owner) is a much smaller model than the general
assistant it was compared with; the kernel can stop it from saying the wrong thing but cannot make it reason better.

## What worked

- **The architecture direction.** Moving reasoning to the model and keeping deterministic guardrails beat the journey
  controller on every dimension but part quality, on both sets.
- **The evidence ledger and verifier** cut invented customer evidence from 19% to 4% (0% held-out); 167 unsupported
  claims were rejected across 301 turns, 7% of turns were regenerated.
- **No fallback.** 2 explicit provider errors in 376 turns, both surfaced as errors; no turn was answered from a template.
- **Safety copy and gates fired** (10 prohibited-advice removals, 19 step precautions, 2 unsafe requests refused on the
  independent 100), and the safety dimension improved over the journey architecture on both sets.

Development changes were made by failure class (verifier false positives, hazard negation, attribution detectors,
calibration and precaution rules in the reasoner prompt), never by case. The held-out set was not run on the new engine
until the candidate was frozen; its expected outcomes were not edited.

## What would be needed to reach the targets

1. **A stronger reasoning model**, or a two-tier design in which the local model handles intake and a stronger model
   reasons. Every model-owned dimension is the gap; the owner fixed the provider for this programme.
2. **Calibration control in the kernel**: a deterministic rule that a cause may be stated as "likely" only with at least
   two discriminating facts, and as certain only with a confirmed test.
3. **Semantic repeat detection** (answered-question tracking by meaning, not wording).
4. **Wider prohibited-advice coverage** (re-running after burning in any phrasing, isolation at the consumer unit for
   hard-wired appliances) and safety copy that is added before the scope reply.
5. **A part gate that requires two independent discriminating facts**, not the model's own "narrowed" label.

Each would need a new development round on the independent 100 and a new, freshly frozen held-out set: this held-out
set has now been seen.
