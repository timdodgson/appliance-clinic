# Approval point A: sandbox controls and toolkit

**Classification:** sandbox only. This is the first AWS mutation of Phase 4 (#34). It runs only after
written approval on #34. Nothing here changes a production AC or S4R resource.

Every document in this folder is generated by `tools/migration/src/sandbox/approval-a.js`
(`npm run sandbox:approval-a`). The tests in `tools/migration/test/sandbox-approval-a.test.js` check
these documents against the sandbox allowlist and both denylists, and CI fails if a committed document
differs from the generator.

## The documents

| File | What it is |
|---|---|
| `ac-operator-policy-sbx.json` | The operator's only allow policy. Sandbox ARN patterns only, plus account-level reads that IAM authorises only on `*`. Toolkit roles can be written only through CloudFormation, and only with the four reviewed managed policies attached |
| `ac-cfn-execution-sbx.json` | The acsbx execution role's allow policy. It is also the **permissions boundary** every sandbox-created role must carry. The only managed policy a sandbox role may get is `AWSLambdaBasicExecutionRole` |
| `ac-deny-production-sbx.json` | Explicit denies, attached to the operator, the execution role and every toolkit role: every production AC and S4R resource; services the sandbox never uses (CloudFront, ACM, Route 53, EC2, RDS, ECS, SES, SNS); KMS key administration; any region but eu-west-1 for regional services; changes to the controls themselves; managed-policy writes; removing boundaries; IAM users and keys |
| `ac-operator-sbx-trust.json` | Only the IAM user who runs this step may assume the operator role. `${OPERATOR_USER_ID}` is filled in at execution from `sts get-caller-identity` and is not committed |
| `ac-budget-sbx.json`, `ac-budget-sbx-notifications.json` | Daily cost budget, $15, email at 80% and 100% of actual spend. `${OWNER_EMAIL}` is filled in at execution and is not committed |
| `bootstrap-stock-v32.json` | The stock CDK bootstrap template, version 32, from `cdk bootstrap --show-template` with aws-cdk 2.1144.0 (YAML SHA-256 `ed382e6eaab4bfddfe9b4fdb5a81fed0dfb7cc1dc6118fb11c41a0381377e89f`) |
| `bootstrap-acsbx.json` | The stock template with four reviewed changes (below) |
| `step-bootstrap.json` | Step file for `check:changeset --mode sandbox` |

### Why the stock bootstrap template is not used

In the stock template, the deploy role holds `cloudformation:CreateChangeSet`, `ExecuteChangeSet`,
`UpdateStack`, `DeleteStack` and `UpdateTerminationProtection` on `Resource: "*"`, and any principal in
the account with an assume-role grant can assume it. In this shared account that would let the sandbox
toolkit change or delete `SparesSite-dev` or `CDKToolkit`. `bootstrap-acsbx.json` changes exactly this:
1. **Parameter defaults are fixed for the sandbox:**
   - qualifier `acsbx`
   - execution policies `ac-cfn-execution-sbx` and `ac-deny-production-sbx`, never `AdministratorAccess`
   - the AWS-managed S3 key
   - no trusted accounts
   - no example boundary
2. **The deploy role is scoped:** its CloudFormation rights cover `stack/*-sbx/*` and
   `stack/ApplianceClinicSandboxToolkit/*` only. The cross-account pipeline statements and the
   stack-refactor statement are removed.
3. **The deny is attached everywhere:** `ac-deny-production-sbx` is attached to the deploy,
   file-publishing, image-publishing and lookup roles.
4. **Retain everywhere:** `DeletionPolicy` and `UpdateReplacePolicy` are `Retain` on every resource, as
   the change-set checker requires.

The bootstrap is deployed as a CloudFormation change set, not with `cdk bootstrap`, so it passes through
`check:changeset --mode sandbox` before it runs.

## Commands

Run from `tools/migration` with AWS CLI v2, region `eu-west-1`. Any non-zero exit, or any guard
`STOP`, ends the step. Report the failure on #34 and run the cleanup for whatever was already created.

```bash
set -euo pipefail
export AWS_REGION=eu-west-1 AWS_DEFAULT_REGION=eu-west-1
A=800960611664
D=../../docs/migration/sandbox/approval-a
O=../../.migration-output/approval-a
TAGS='Key=ac:sandbox,Value=phase-4'
mkdir -p "$O"
```

### 0. Pre-flight (read-only)

```bash
npm ci
npm run sandbox:approval-a -- --check                         # committed documents = generator
npm test                                                      # includes the approval-A proofs
npm run inventory -- --expect-account $A --out "$O/inventory-before"
npm run denylist -- --inventory "$O/inventory-before"         # S4R denylist regenerated today
git diff --exit-code ../../docs/migration/s4r-denylist.json   # STOP if S4R has changed
npm run baseline -- s4r-health --live                         # STOP if S4R is unhealthy
npm run sandbox:guard -- caller --bootstrap                   # account and region
for t in "AWS::IAM::ManagedPolicy ac-deny-production-sbx" "AWS::IAM::ManagedPolicy ac-cfn-execution-sbx" \
         "AWS::IAM::ManagedPolicy ac-operator-policy-sbx" "AWS::IAM::Role ac-operator-sbx" \
         "AWS::Budgets::Budget ac-budget-sbx" "AWS::CloudFormation::Stack ApplianceClinicSandboxToolkit"; do
  set -- $t; npm run -s sandbox:guard -- target --type "$1" --id "$2"
done
```

### 1. Managed policies (as the IAM user)

```bash
aws iam create-policy --policy-name ac-deny-production-sbx --policy-document file://$D/ac-deny-production-sbx.json --tags $TAGS
aws iam create-policy --policy-name ac-cfn-execution-sbx   --policy-document file://$D/ac-cfn-execution-sbx.json   --tags $TAGS
aws iam create-policy --policy-name ac-operator-policy-sbx --policy-document file://$D/ac-operator-policy-sbx.json --tags $TAGS
```

### 2. Operator role (as the IAM user)

```bash
OPERATOR_USER_ID=$(aws sts get-caller-identity --query UserId --output text)
sed "s/\${OPERATOR_USER_ID}/$OPERATOR_USER_ID/" $D/ac-operator-sbx-trust.json > "$O/trust.json"
aws iam create-role --role-name ac-operator-sbx --assume-role-policy-document file://$O/trust.json \
  --max-session-duration 3600 --description "Appliance Clinic Phase 4 sandbox operator (#34)" --tags $TAGS
aws iam attach-role-policy --role-name ac-operator-sbx --policy-arn arn:aws:iam::$A:policy/ac-operator-policy-sbx
aws iam attach-role-policy --role-name ac-operator-sbx --policy-arn arn:aws:iam::$A:policy/ac-deny-production-sbx
```

### 3. Budget (as the IAM user)

```bash
sed "s/\${OWNER_EMAIL}/$OWNER_EMAIL/" $D/ac-budget-sbx-notifications.json > "$O/notifications.json"
aws budgets create-budget --region us-east-1 --account-id $A --budget file://$D/ac-budget-sbx.json \
  --notifications-with-subscribers file://$O/notifications.json --resource-tags $TAGS
```

### 4. Become the operator

```bash
eval "$(aws sts assume-role --role-arn arn:aws:iam::$A:role/ac-operator-sbx --role-session-name approval-a \
  --duration-seconds 3600 --query 'Credentials.[AccessKeyId,SecretAccessKey,SessionToken]' --output text \
  | awk '{print "export AWS_ACCESS_KEY_ID="$1" AWS_SECRET_ACCESS_KEY="$2" AWS_SESSION_TOKEN="$3}')"
npm run sandbox:guard -- caller                               # must PASS without --bootstrap
```

### 5. Toolkit stack (as the operator)

```bash
S=ApplianceClinicSandboxToolkit; C=approval-a-bootstrap
aws cloudformation create-change-set --stack-name $S --change-set-name $C --change-set-type CREATE \
  --template-body file://$D/bootstrap-acsbx.json --capabilities CAPABILITY_NAMED_IAM --tags $TAGS
aws cloudformation wait change-set-create-complete --stack-name $S --change-set-name $C
aws cloudformation describe-change-set --stack-name $S --change-set-name $C > "$O/changeset.json"
npm run check:changeset -- --changeset "$O/changeset.json" --mode sandbox \
  --step $D/step-bootstrap.json --template $D/bootstrap-acsbx.json
# Expect PASS and exactly the eleven Add actions above. On FAIL: delete-change-set, then STOP.
aws cloudformation execute-change-set --stack-name $S --change-set-name $C
aws cloudformation wait stack-create-complete --stack-name $S
aws cloudformation update-termination-protection --enable-termination-protection --stack-name $S
```

### 6. Verify (read-only)

```bash
aws cloudformation describe-stack-resources --stack-name $S \
  --query 'StackResources[].[LogicalResourceId,ResourceType,PhysicalResourceId,ResourceStatus]' --output table
# Back as the IAM user (unset AWS_SESSION_TOKEN and the operator keys):
npm run inventory -- --expect-account $A --out "$O/inventory-after"
npm run compare:config -- "$O/inventory-before" "$O/inventory-after"   # expect 0 production differences
npm run baseline -- s4r-health --live
```

## Cleanup and rollback

Run as the IAM user, by allowlisted name only, each preceded by `sandbox:guard -- target`. Everything
created here is empty when Phase 4 starts, so the full cleanup takes about ten minutes.

```bash
aws cloudformation update-termination-protection --no-enable-termination-protection --stack-name ApplianceClinicSandboxToolkit
aws cloudformation delete-stack --stack-name ApplianceClinicSandboxToolkit   # Retain: the resources stay
aws cloudformation wait stack-delete-complete --stack-name ApplianceClinicSandboxToolkit
aws s3 rb s3://cdk-acsbx-assets-$A-eu-west-1 --force
aws ecr delete-repository --repository-name cdk-acsbx-container-assets-$A-eu-west-1 --force
aws ssm delete-parameter --name /cdk-bootstrap/acsbx/version
for r in file-publishing image-publishing lookup deploy cfn-exec; do
  R=cdk-acsbx-$r-role-$A-eu-west-1
  for p in $(aws iam list-attached-role-policies --role-name $R --query 'AttachedPolicies[].PolicyArn' --output text); do aws iam detach-role-policy --role-name $R --policy-arn $p; done
  for p in $(aws iam list-role-policies --role-name $R --query 'PolicyNames[]' --output text); do aws iam delete-role-policy --role-name $R --policy-name $p; done
  aws iam delete-role --role-name $R
done
aws budgets delete-budget --region us-east-1 --account-id $A --budget-name ac-budget-sbx
aws iam detach-role-policy --role-name ac-operator-sbx --policy-arn arn:aws:iam::$A:policy/ac-operator-policy-sbx
aws iam detach-role-policy --role-name ac-operator-sbx --policy-arn arn:aws:iam::$A:policy/ac-deny-production-sbx
aws iam delete-role --role-name ac-operator-sbx
for p in ac-operator-policy-sbx ac-cfn-execution-sbx ac-deny-production-sbx; do aws iam delete-policy --policy-arn arn:aws:iam::$A:policy/$p; done
```

Then re-run the inventory and `compare:config`, and confirm that no allowlisted name exists.

## Cost

- **IAM, STS, CloudFormation, SSM** (standard parameter): no charge.
- **AWS Budgets:** no charge. The account has no other budget, and the first two are free.
- **S3 bucket and ECR repository:** empty at this step, so no charge. KMS: no customer key is created.
- **Expected:** $0.00 a month until Phase 4 rehearsals put artefacts in them. Rehearsal costs are planned
  per batch at approval point B.

## Accepted limits

- **Budget scope.** The budget is account-wide, because a tag-scoped budget needs the `ac:sandbox` cost
  allocation tag activated. That is an account-level billing change, which Phase 4 excludes. Production
  runs at about $7.60 a day (October 2026), so a day above $15 means something new is spending.
- **The boundary on sandbox roles.** It is a difference from production: production roles have none.
  Phase 4 imports declare it, and Phase 5 must not copy it. It does not affect T1 to T7, which concern
  inline policies.
- **Residual trust.** The operator can create CloudFormation stacks named `*-sbx`. The checker and review
  of each change set are the control against a deliberately harmful sandbox template. The explicit deny
  still blocks every production AC and S4R resource it lists, for every toolkit and sandbox role.
